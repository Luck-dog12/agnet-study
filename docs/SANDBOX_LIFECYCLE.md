# 云沙箱生命周期与时长控制

更新日期：2026-11-08。

远端会话按需创建云沙箱：启用远端后端、启动 Agent、查看 `/status` 本身都不会创建实例。首次需要远端工作区的工具才创建一组沙箱，其中一个用于执行项目命令，另一个用于通过宿主受控接口访问 OSS。

## 默认限制

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `ALIYUN_SANDBOX_TIMEOUT_SECONDS` | 300 秒 | 范围 30–3600 秒。每次申请的云端租约时长；活动工具需要时会续期，但不能超过会话剩余时长。 |
| `ALIYUN_SANDBOX_IDLE_TIMEOUT_SECONDS` | 120 秒 | 范围 30–3600 秒。没有活动工具或审批保留时，达到空闲上限就销毁这一组实例。 |
| `ALIYUN_SANDBOX_MAX_SESSION_SECONDS` | 3600 秒 | 范围 60–86400 秒。同一会话累计沙箱组驻留时长上限，包含创建、初始化和空闲等待。 |

“一组驻留 60 秒”在本地预算中计为 60 秒，而不是两个实例相加的 120 秒。云厂商仍按两个实例各自的规格和存活时长计费，OSS 存储费用也独立存在。因此这里控制的是使用时长，不是账单金额，也不是账号级总预算。多个独立会话各自有自己的上限。

## 自动回收与恢复

工具正在执行、异步工具尚未结束或工具仍持有审批保留时，不按空闲状态回收。活动期间会给两个实例续期，每次续期都受累计上限约束。初始化阶段不续期；如果工作区恢复耗时超过首次租约，启动会安全失败，需要根据工作区规模调高 `ALIYUN_SANDBOX_TIMEOUT_SECONDS`。

工具结束后开始计算空闲时间。空闲回收会同时销毁执行实例和持久化实例，并在终端提示。之后新工具需要远端工作区时，会创建新实例并恢复已保存到 OSS 的工作区文件，不需要新增手动解锁命令。

恢复范围限于已经持久化的工作区内容。临时内存、进程、未保存到检查点的文件以及工作区之外的临时产物不会保留。回收后的重建不会重放上一次用户命令。

累计上限是硬限制，即使有长任务正在运行也不能无限续期。达到上限、续期失败或无法确认安全清理时，会停止接受新的远端执行并提示用户；已开始操作可能被终止。未知结果仍需要按既有恢复检查流程核验，系统不会自动重放有副作用的命令，也不会自动切换到本机执行。

为覆盖云端请求的网络耗时，系统会预留安全余量。剩余时长不足以安全创建或续期时，会略早于显示的累计上限停止，预算不是精确计费计时器。

正常退出会主动销毁实例。进程被强制结束或主机失联时，最后一次云端租约仍会到期；下一次恢复会话时还会按会话身份清理残留实例。运行中的回收按实例组身份隔离，旧进程延迟清理不会删除后续重建的新组。该机制使用销毁与重建，不依赖云平台的休眠白名单功能。

阿里云的 `set_timeout(seconds)` 是从本次调用开始重新计时，执行命令本身不会重置到期时间，见[官方超时说明](https://help.aliyun.com/zh/functioncompute/hibernation-and-recovery)。

## 会话预算与状态

预算记录保存在会话目录的 `sandbox-budget.json`，由宿主通过独立文件锁和进程所有权校验更新。空闲销毁到下一次重建之间的时间不计入使用量。同一会话的重启与 `--resume` 不会清零预算；异常退出无法确认实际回收时刻时，会按已经预留的租约时长保守结算，避免重启绕过上限。

预算记录损坏、身份不匹配或无法安全写入时，远端执行会停止启动，不会静默建立一份零预算。不要删除预算记录来继续旧会话。

输入 `/status` 可查看沙箱状态、已使用与剩余秒数、空闲上限、云端租约和累计上限。尚未初始化运行时时，会显示 `sandbox_state=not_created` 以及“待加载”；此时不会为了显示状态接管预算记录或创建云资源。“本进程尚未创建”不代表云账号内没有其他会话或异常退出遗留的实例。

## 配置示例

在项目 `.env` 中设置以下值，然后重启 Agent。也可以在当前 PowerShell 中覆盖：

```powershell
$env:ALIYUN_SANDBOX_TIMEOUT_SECONDS = "300"
$env:ALIYUN_SANDBOX_IDLE_TIMEOUT_SECONDS = "120"
$env:ALIYUN_SANDBOX_MAX_SESSION_SECONDS = "3600"
.\agent.cmd --resume sandbox-demo
```

新远端会话仍需要显式启用沙箱配置并提供有效云凭据；这些时间参数不会自动开启云服务。现有会话的后端绑定保持不变，`partial-control` / `full-access` 权限模式也不会绕过生命周期限制。
